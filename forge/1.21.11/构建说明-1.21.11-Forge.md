# VPlayer 1.21.11（Forge）构建说明

本工程是 VPlayer 的 **Minecraft 1.21.11 + Forge 61.2.5** 版本，功能与已交付的
1.21.11 NeoForge / 1.21.1 Forge / 1.20.1 各版本一致。源码主体来自
`minecraft-video-player-1.21.11-neoforge`（MC 1.21.11 的正确实现），Forge 侧写法参考
已实机验证的 `minecraft-video-player-1.21.1-forge`，构建骨架来自官方
**Forge 1.21.11-61.2.5 MDK**（ForgeGradle 7 + Gradle 9.5.0）。

## 1. 环境要求

| 项目 | 版本 |
| --- | --- |
| JDK（编译/运行） | **Java 21**（`C:\Program Files\Java\jdk-21`，实测 21.0.9） |
| JDK（构建工具链） | **Java 25**（ForgeGradle 7 的 Minecraft Mavenizer 要求，见下） |
| Gradle | 9.5.0（工程自带 wrapper，`gradle-wrapper.properties` 指向腾讯云镜像） |
| Minecraft | 1.21.11（official 映射，**不需要 reobf**） |
| Forge（编译） | 1.21.11-**61.2.5** |
| 构建插件 | ForgeGradle `[7.0.3,8)`（本机实际解析到 7.0.40） |

### ⚠️ 构建前置：JDK 25 与工具链路径

ForgeGradle 7 的 **Minecraft Mavenizer 0.5.21 是 Java 25 编译的**（class 文件版本 69），
Gradle 会用 Java 25 工具链去执行它。因此除了编译/运行用的 Java 21，还需要额外装一个 JDK 25：

- 示例路径：`C:\Program Files\Java\jdk-25`（Temurin 25.0.5+8，可从 Adoptium / 清华镜像下载）
- 如果你的 JDK 25 不在 Gradle 默认探测位置，在工程 `gradle.properties` 里取消注释并改成实际路径：
  ```properties
  org.gradle.java.installations.paths=C\:\\path\\to\\jdk-25
  org.gradle.java.installations.auto-download=false
  ```
  （关闭自动下载：foojay 会去 GitHub 下载，国内网络常不通。）

**编译目标和游戏运行仍然是 Java 21**。

## 2. 构建

Windows（本机全局 Gradle 代理是死的，必须命令行覆盖）：

```powershell
$env:JAVA_HOME="C:\Program Files\Java\jdk-21"
cd <工程目录>
.\gradlew.bat build fatJar --no-daemon -Dhttp.proxyHost= -Dhttp.proxyPort= -Dhttps.proxyHost= -Dhttps.proxyPort=
```

产物：`build\libs\vplayer-1.0.0-all.jar`（约 121.8 MB，内含 FFmpeg/JavaCV 原生库，
64 个 Windows dll）。

- 首次构建会由 Mavenizer 下载并反编译 MC 1.21.11 + Forge 61.2.5，耗时约 15 分钟；
  之后增量构建 1 分钟内完成。
- `build` 产物 `vplayer-1.0.0.jar` 是瘦 jar，只有模组自身类与资源；
  安装/分发用 `vplayer-1.0.0-all.jar`，改名成 `VPlayer-1.21.11-Forge.jar` 放进 `mods\`。
- 只保留 Windows 的 ffmpeg + javacpp 原生库；opencv/tesseract/openblas 等多余模块与
  其它平台原生库全部排除（与其它版本成品保持一致）。
- 工程 `gradle.properties` 已关闭 `org.gradle.configuration-cache`：自定义 `fatJar` 任务在
  配置缓存下有兼容问题。

## 3. 构建系统要点 / 坑

1. **构建骨架 = 官方 Forge 1.21.11 MDK**，不要抄 1.20.1（ForgeGradle 6 + reobf）或
   1.21.1（ForgeGradle 6 + `reobf=false`）的 build.gradle。
2. ForgeGradle 7 的仓库 DSL 是 `minecraft.mavenizer(it)` / `fg.forgeMaven` /
   `fg.minecraftLibsMaven`，依赖写法是
   `implementation minecraft.dependency('net.minecraftforge:forge:1.21.11-61.2.5')`；
   **Mavenizer 仓库必须放在 repositories 最前面**。
3. 1.21.11 Forge 运行时就是 official 映射，`fatJar` 的类直接取 `sourceSets.main.output`，
   没有 reobf 步骤。
4. `annotationProcessor 'net.minecraftforge:eventbus-validator:7.0.5'`（MDK 默认项）保留。
5. Compile 用的 JavaCV：`compileOnly 'org.bytedeco:javacv:1.5.11'`（Java 类），
   `natives 'org.bytedeco:javacv-platform:1.5.11'` 只用于 fatJar 打包原生库。

## 4. 主要移植点（NeoForge 1.21.11 → Forge 61.2.5）

- **入口**：`@Mod` 构造器注入 `FMLJavaModLoadingContext`，用
  `context.getModBusGroup()` 得到 `BusGroup`；`DeferredRegister.register(BusGroup)`。
- **注册表**：`DeferredRegister.create(ForgeRegistries.BLOCKS/ITEMS, MODID)` /
  `DeferredRegister.create(Registries.BLOCK_ENTITY_TYPE, MODID)` + `RegistryObject<T>`；
  1.21.11 起 Block/Item 的 Properties 必须带 id：
  `BlockBehaviour.Properties.of().setId(BLOCKS.key("screen"))` /
  `new Item.Properties().setId(ITEMS.key("screen"))`。
- **方块实体类型**：1.21.11 正式版的 `BlockEntityType` 构造器参数是 `Set<Block>`
  （Forge 用 AT 把它开放为 public）：
  `new BlockEntityType<>(ScreenBlockEntity::new, Set.of(ModBlocks.SCREEN.get()))`。
- **事件（Forge 61 用 eventbus 7）**：没有旧式 `IEventBus.addListener` 的笼统注册，
  事件类自带静态 `BUS`（默认总线组）/ `getBus(BusGroup)`（模组总线组）：
  - `FMLClientSetupEvent.getBus(modBusGroup).addListener(...)`
  - `EntityRenderersEvent.RegisterRenderers.BUS.addListener(...)`
  - `TickEvent.ClientTickEvent.Post.BUS.addListener(...)`
  - `PlayerEvent.PlayerLoggedOutEvent.BUS.addListener(...)`
  - `BuildCreativeModeTabContentsEvent.BUS.addListener(...)`
  - `@SubscribeEvent` 在 `net.minecraftforge.eventbus.api.listener.SubscribeEvent`
- **网络层**：Forge 61 仍提供 1.21.1 那套
  `ChannelBuilder.named(Identifier.fromNamespaceAndPath(...)).networkProtocolVersion(1).simpleChannel()`
  → `SimpleChannel.messageBuilder(Class, id).encoder(...).decoder(...).consumerMainThread(...).add()`，
  handler 上下文是 `net.minecraftforge.event.network.CustomPayloadEvent.Context`
  （`getSender()` / `isClientSide()`）。发送：
  `CHANNEL.send(msg, PacketDistributor.SERVER.noArg())`（C→S）、
  `CHANNEL.send(msg, PacketDistributor.TRACKING_CHUNK.with(levelChunk))`（S→C）。
  业务逻辑（编解码字段、handle 内的屏幕组处理）照抄 NeoForge payload。
- **方块实体同步**：Forge 61 的 `IForgeBlockEntity.handleUpdateTag(ValueInput, HolderLookup.Provider)`
  **多一个 registry 参数**（NeoForge 版是一参）：`
  public void handleUpdateTag(ValueInput input, HolderLookup.Provider provider)`，
  内部先 `loadWithComponents(input)` 再把 url/loop 同步给 `VideoEngine`。
- **原生库加载**：沿用 `VPlayerNatives`（把 dll 解压到 `<gameDir>\vplayer-natives\`，
  在**任何 JavaCPP 类初始化之前**设置 `org.bytedeco.javacpp.pathsfirst` / `cachedir` /
  `platform.preloadpath`，再 `Loader.load`）。正式环境找模组 jar 用 Forge 的
  `ModList.get().getModFileById(MODID).getFile().getFilePath()`。
- **1.21.11 渲染新管线**（照 1.21.11 NeoForge 工程，Forge 侧无改动）：
  `BlockEntityRenderer<T, S extends BlockEntityRenderState>` 拆
  `createRenderState()` / `extractRenderState(...)` / `submit(S, PoseStack, SubmitNodeCollector, CameraRenderState)`，
  自定义四边形用 `collector.submitCustomGeometry(...)`，材质用
  `net.minecraft.client.renderer.rendertype.RenderTypes`。
- **1.21.11 其它**：`ResourceLocation` 已改名 `net.minecraft.resources.Identifier`
  （`Identifier.fromNamespaceAndPath`）；方块实体 save/load 用 `ValueOutput`/`ValueInput`。

## 5. 元数据 / 资源（1.21.11 格式）

- `src/main/resources/META-INF/mods.toml`（**不是** `neoforge.mods.toml`）：
  `modLoader="javafml"`、`loaderVersion="[61,)"`，依赖 `forge [61,)` 与
  `minecraft [1.21.11,1.22,)`。
- `src/main/resources/pack.mcmeta`：1.21.11 的新格式字段
  `{"pack":{"description":...,"max_format":94,"min_format":[94,1]}}`。
- 其余资源直接沿用 1.21.11 NeoForge 工程：
  - `assets/vplayer/items/screen.json`（1.21.11 物品定义，`minecraft:model` 指向 `vplayer:item/screen`）
  - `assets/vplayer/models/{block,item}/screen.json`、`blockstates/screen.json`、`lang/{en_us,zh_cn}.json`、3 张纹理
  - `data/vplayer/recipe/screen.json`（单数 `recipe/`，key 直接写字符串，result `{"id":..,"count":4}`）
  - `data/vplayer/loot_table/blocks/screen.json`（单数 `loot_table/`，含 `random_sequence`）

## 6. 自检（游戏内自动测试）

游戏目录放 `vplayer-selftest.txt`（内容为一个视频文件绝对路径，或 http(s) URL），
启动后模组自动：摆 11×6 大屏 → 按南/北/东/西/朝下 + 不规则屏 + L 形屏依次播放并截图
→ 测暂停续播、挖掘掉落、3D 物品图标、控制界面 → 写 `vplayer-selftest-result.txt` 并自动退出。

通过标准：结果文件含
`OK 全部朝向 + 不规则屏幕 + L 形屏幕 + 暂停续播 + 挖掘掉落 + 图标`。

隔离测试实例（开发者自测用）：独立 gameDir，只读复用游戏目录的
`libraries`/`assets`/`versions\1.21.11-Forge_61.2.5`，jdk-21 启动、真实 Forge 61.2.5 生产环境。
启动脚本需存成 UTF-8 BOM；运行前 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`。

## 7. 已知说明 / 1.21.11 移植坑

- **1.21.11 的 `GuiGraphics.drawString(..., int color)` 颜色必须带 alpha**：
  1.21.11 起 `drawString` 内部有 `if (ARGB.alpha(color) != 0)` 判断，只写 `0xRRGGBB`
  （alpha=0）的文字**完全不会渲染**。控制界面里所有文字颜色都要写成 `0xFFRRGGBB`
  （已知问题：控制界面文字/音量数字不显示，已修）。
- 停止/切换视频时解码线程会打一条 `InterruptedException: sleep interrupted` 的 ERROR 日志，
  这是 1.20.1 / 1.21.1 同款既有行为（stop 时主动 interrupt 线程），不影响功能。
- 离线测试实例启动时会有一条 Realms 鉴权失败 ERROR（无正版登录），与模组无关。
- 已知问题：“准星靠近屏幕时画面亮度会变暗”，暂不处理（与其它版本渲染代码相同）。
- 音频输出用 `javax.sound.sampled`，与其它版本实现相同。
