# VPlayer 1.21.1（Forge）构建说明

本工程是 VPlayer 的 **Minecraft 1.21.1 + Forge（52.x）** 版本，功能与已交付的
1.21.1 NeoForge / 1.20.1 Forge 版一致。源码主体来自 1.21.1 NeoForge 工程
（MC 1.21.1 的正确实现），构建系统与 Forge API 写法参考 1.20.1 Forge 工程 +
官方 1.21.1 MDK。

## 1. 环境要求

| 项目 | 版本 |
| --- | --- |
| JDK | **Java 21**（`JAVA_HOME` 指向 `C:\Program Files\Java\jdk-21`） |
| Gradle | 8.10.2（工程自带 wrapper，`gradle-wrapper.properties` 指向腾讯云镜像） |
| Minecraft | 1.21.1 |
| Forge（编译） | 1.21.1-**52.1.21** |
| 构建插件 | ForgeGradle `[6.0.24,6.2)`（本机实际解析到 6.0.54） |

> 1.21.1 起 Forge 运行时使用 **official 映射**，因此 `build.gradle` 里 `reobf = false`，
> 不需要 reobf；`build` 产物里的类就是最终运行用类（与 1.20.1 不同，注意别照搬旧流程）。

## 2. 构建

Windows：

```powershell
$env:JAVA_HOME="C:\Program Files\Java\jdk-21"
cd <工程目录>
.\gradlew.bat build fatJar --no-daemon
```

产物：`build\libs\vplayer-1.0.0-all.jar`（约 116 MB，内含 FFmpeg/JavaCV 原生库，64 个 Windows dll）。

- 只保留 Windows 的 ffmpeg + javacpp 原生库；opencv/tesseract/openblas 等多余模块与其它平台
  原生库全部排除（与 1.21.1 NeoForge 成品保持一致）。
- 安装/分发用 `vplayer-1.0.0-all.jar`，改名成 `VPlayer-1.21.1-Forge.jar` 放进 `mods\` 即可。

### 本机注意：全局 Gradle 代理配置

本机 `%USERPROFILE%\.gradle\gradle.properties` 里配了 `127.0.0.1:7897` 的 http/https 代理，
但该代理当前未运行，会导致 Gradle 无法下载依赖。本次构建使用命令行覆盖：

```powershell
.\gradlew.bat build fatJar --no-daemon -Dhttp.proxyHost= -Dhttp.proxyPort= -Dhttps.proxyHost= -Dhttps.proxyPort=
```

（或临时注释掉上述 gradle.properties 里的 `systemProp.*proxy*` 行。）

## 3. 构建系统要点 / 坑

1. **ForgeGradle 版本**：Forge 1.21.1 官方 MDK 从 52.1.13 起迁移到 ForgeGradle 7，
   但 52.1.12 及以前的 ForgeGradle 6 配置同样可用（本工程用 6.0.54 + Gradle 8.10.2 构建成功）。
2. **`reobf = false`**：1.21.1 Forge 运行时就是 official 映射，无需 reobf。`fatJar` 的类直接取
   `sourceSets.main.output`，不能再去依赖 1.20.1 的 `build\reobfJar\output.jar`。
3. **fatJar**：模组类+资源 + JavaCV/FFmpeg 类和 dll；类与资源都从 `sourceSets.main.output` 取。
4. **依赖**：`compileOnly 'org.bytedeco:javacv:1.5.11'`（Java 类），
   `natives 'org.bytedeco:javacv-platform:1.5.11'` 只用于 fatJar 打包原生库。
5. **maven**：`maven.minecraftforge.net`（Forge userdev / MCP 数据）+ Maven Central（JavaCV）。
6. **元数据**：`META-INF/mods.toml`（不是 NeoForge 的 `neoforge.mods.toml`）：
   `modLoader="javafml"`、`loaderVersion="[52,)"`、依赖 `forge [52,)` 与 `minecraft [1.21.1,1.22)`。
   `pack.mcmeta` 的 `pack_format = 48`；数据包目录用 **单数**：
   `data/vplayer/recipe/`、`data/vplayer/loot_table/`，配方 `result: {"id":..,"count":..}`。

## 4. 主要移植点（NeoForge 1.21.1 → Forge 1.21.1）

- `net.neoforged.*` → `net.minecraftforge.*`：
  `fml.common.Mod` / `fml.javafmlmod.FMLJavaModLoadingContext` / `fml.loading.FMLEnvironment` /
  `eventbus.api.IEventBus|SubscribeEvent` / `event.BuildCreativeModeTabContentsEvent` /
  `event.RegisterCommandsEvent` / `client.event.EntityRenderersEvent` /
  `event.TickEvent.ClientTickEvent + Phase.END` / `event.entity.player.PlayerEvent`。
- **@Mod 构造器**：Forge 1.21.1 用 `public VPlayerMod(FMLJavaModLoadingContext context)`，
  由 `context.getModEventBus()` 取模组事件总线（官方 1.21.1 MDK 写法）。
- **注册表**：`DeferredRegister.create(ForgeRegistries.BLOCKS/ITEMS/BLOCK_ENTITY_TYPES, MODID)`
  + `RegistryObject<T>`（NeoForge 的 DeferredBlock/DeferredItem/DeferredHolder 都换掉）。
- **网络层（重点）**：Forge 1.21.1 的网络 API 已重写，**不是** 1.20.1 的
  `net.minecraftforge.network.simple.SimpleChannel`，也不是 NeoForge 的 payload：
  - `net.minecraftforge.network.ChannelBuilder.named(...).networkProtocolVersion(int).simpleChannel()`
  - `SimpleChannel.messageBuilder(Class, id).encoder(...).decoder(...).consumerMainThread((msg,ctx)->...).add()`
  - handler 上下文是 `net.minecraftforge.event.network.CustomPayloadEvent.Context`
    （`ctx.getSender()` / `ctx.isClientSide()` / `ctx.enqueueWork` / `ctx.setPacketHandled`）。
  - 发送：`CHANNEL.send(msg, PacketDistributor.PLAYER.with(player))`、
    `CHANNEL.send(msg, PacketDistributor.TRACKING_CHUNK.with(levelChunk))`（注意 WITH 直接收对象，
    不是 Supplier）、客户端发给服务端用 `CHANNEL.send(msg, PacketDistributor.SERVER.noArg())`。
  - 参考：`net/minecraftforge/network/{ChannelBuilder,SimpleChannel,PacketDistributor}.java`
    （Forge 1.21.1 源码包 `forge-1.21.1-52.1.21-sources.jar`）。
- **BlockEntity**：1.21.1 的 `saveAdditional(CompoundTag, HolderLookup.Provider)` /
  `loadAdditional(...)` / `getUpdateTag(HolderLookup.Provider)` 等签名从 1.21.1 NeoForge 工程沿用。
- **原生库加载**：沿用 1.20.1 Forge 工程验证过的 `VPlayerNatives`（在任何 JavaCPP 类初始化前
  设置 `org.bytedeco.javacpp.pathsfirst` / `cachedir` / `platform.preloadpath`，再 `Loader.load`）。

## 5. ⚠️ 已知环境问题与兼容修补（重要）

本机实测 **Forge 52.1.21 生产环境**里，进入世界时 Forge 内部的
`AddReloadListenerEvent` 不会触发（**不放任何模组、纯 Forge 也会复现**），导致 Forge 的
`LootModifierManager` 从未初始化。之后世界里**任何方块掉落**（挖草、水流冲掉植物、火焰烧掉
方块等）都会抛
`IllegalStateException: Can not retrieve LootModifierManager until resources have loaded once`
并崩游戏。

本模组做了兼容修补（`VPlayerClient.ForgeLootFix`）：进入单人世界后先做一次无害的掉落查询，
若发现掉落管理器未初始化，就补发一次 `AddReloadListenerEvent` 让 Forge 初始化它
（日志会打印「已修补 Forge 掉落管理器初始化缺失（Forge 52.1.x 环境兼容）」）。

- 事件正常触发的环境里掉落查询会直接成功、补丁不生效，**不影响任何已加载的全局掉落修饰器**。
- 该修补只覆盖单人游戏客户端；若以后在 Forge 52.1.x 服务端/多人环境遇到同类崩溃，需要
  换 Forge 版本或等服务端修复。

其它已知说明：
- 停止/切换视频时解码线程会打一条 `InterruptedException: sleep interrupted` 的 ERROR 日志，
  这是 1.21.1 / 1.20.1 同款既有行为（stop 时主动 interrupt 线程），不影响功能。
- 已知问题：“准星靠近屏幕时画面亮度会变暗”，暂不处理（与其它版本渲染代码相同）。
- 音频输出用 `javax.sound.sampled`，与 1.21.1 版实现相同。

## 6. 自检（游戏内自动测试）

游戏目录放 `vplayer-selftest.txt`（内容为一个视频文件的绝对路径，或 http(s) URL），
启动后模组会自动：摆 11×6 大屏 → 按南/北/东/西/朝下 + 不规则屏 + L 形屏依次播放并截图
→ 测暂停续播、挖掘掉落、3D 物品图标、控制界面 → 写 `vplayer-selftest-result.txt` 并自动退出。

通过标准：结果文件内容为
`OK 全部朝向 + 不规则屏幕 + L 形屏幕 + 暂停续播 + 挖掘掉落 + 图标`。

隔离测试实例（开发者自测用）：独立 gameDir，只读复用游戏目录的
`libraries`/`assets`/`versions\1.21.1-Forge_52.1.21`，不影响你自己的游戏实例。

运行前：`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`（启动脚本是 UTF-8 BOM）。

隔离实例测试记录（全部通过）：
1. `test960.mp4` 本地文件：结果 `OK 全部朝向 + 不规则屏幕 + L 形屏幕 + 暂停续播 + 挖掘掉落 + 图标`，
   截图人工核对：画面单一完整无重影/接缝，L 形内拐角实心边框，3D 图标，控制界面地址回显。
2. `audio-test.mp4`（带 AAC 音轨）：`视频流已打开 640x360 音频=2ch/44100Hz`、
   `音频输出已打开: 44100Hz 2ch`、`音频数据开始写入`，自检 OK。
3. 网络 URL：本地 HTTP Range 服务 `http://127.0.0.1:8123/test960.mp4?upos=1`
   （`?upos` 触发 B 站 UA/Referer 分支）：服务端日志确认 Range 206、UA 为 Chrome、
   `Referer: https://www.bilibili.com`；自检 OK。
4. 正常游玩冒烟（游戏目录没有 `vplayer-selftest.txt`）：模组正常加载、进世界、自检不触发、
   ERROR/FATAL 仅为已知的 stop 时 sleep interrupted。
5. 对照组实验：**不放模组的纯 Forge 实例**同样出现 `LootModifierManager` 崩溃 →
   确认该问题属于 Forge 环境而非本模组。
