# VPlayer 1.20.1（Forge）构建说明

本工程是 VPlayer 的 **Minecraft 1.20.1 + Forge（47.4.x）** 版本。
功能与 1.21.1 / 1.20.1 NeoForge 版完全一致；源码直接复用已完工并实机验证过的
`minecraft-video-player-1.20.1-neoforge` 工程（1.20.1 这条版本线 Forge 与 NeoForge
的包名都是 `net.minecraftforge.*`），只把构建系统从 ModDevGradle(legacyforge) 换成
ForgeGradle，并调整 `mods.toml` 的依赖版本范围。

## 1. 环境要求

| 项目 | 版本 |
| --- | --- |
| JDK | **Java 17**（`JAVA_HOME` 指向 JDK 17） |
| Gradle | 8.10.2（工程自带 wrapper，`gradle-wrapper.properties` 已指向腾讯云镜像） |
| Minecraft | 1.20.1 |
| Forge（编译） | 1.20.1-**47.4.28** |
| 构建插件 | ForgeGradle `[6.0,6.2)`（本机实际解析到 6.0.54） |

> 实测运行环境：**Forge 1.20.1-47.4.29**（真实客户端实例）。
> `mods.toml` 里 forge 依赖为 `[47,)`，47.4.x 各补丁版本通用；编译时用 47.4.28。

## 2. 构建

Windows：

```powershell
$env:JAVA_HOME="C:\Program Files\Java\jdk-17"
cd <工程目录>
.\gradlew.bat build fatJar --no-daemon
```

产物：`build\libs\vplayer-1.0.0-all.jar`（约 116 MB，内含 FFmpeg/JavaCV 原生库）。

- `build` 会执行 ForgeGradle 的 `reobfJar`，把模组类 reobf 成 1.20.1 运行时需要的
  SRG 名称；`fatJar` 再把 JavaCV/FFmpeg 的类和 **64 个 Windows dll** 合并进去。
- 只保留 Windows 原生库；opencv/tesseract/openblas 等多余模块与其它平台原生库全部排除
  （多余模块会导致原生库加载冲突，与 1.21.1 成品保持一致）。
- 安装/分发用 `vplayer-1.0.0-all.jar`，改名成 `VPlayer-1.20.1-Forge.jar` 放进 `mods\` 即可。

## 3. 构建系统要点 / 本机坑（build.gradle 里已写好）

1. **reobfJar 命令行长度（关键坑）**：ForgeGradle 的 `reobfJar` 会把编译 classpath
   里的 jar 逐个作为 `--lib` 参数传给 renamer。如果 `compileOnly` 用
   `org.bytedeco:javacv-platform:1.5.11`（会带出 200 多个平台 jar），Windows 下命令行
   超过 32K，报 `CreateProcess error=206, 文件名或扩展名太长`，reobf 失败。
   解决：`compileOnly` 只依赖 `org.bytedeco:javacv:1.5.11`（Java 类；ffmpeg/javacpp 作为
   传递依赖进来），平台工件 `javacv-platform` 只放进 `natives` 配置供 `fatJar` 打包。
   改完后 reobfJar 的 `--lib` 约 128 个，命令行长度正常。
2. **fatJar 只能从 reobf 产物取类**：类必须来自 `build\reobfJar\output.jar`（已 reobf），
   资源（assets/data/pack.mcmeta/META-INF/mods.toml）另从 `sourceSets.main.output.resourcesDir`
   取。混入未 reobf 的类会在运行时抛 `NoSuchFieldError` / `NoSuchMethodError`。
3. ForgeGradle 6 的 `reobfJar` 实现会**原地改名** `build\libs\vplayer-1.0.0.jar`
   （任务类型 `RenameJarInPlace`），`build\reobfJar\output.jar` 是它的副本，两者内容等价；
   不要拿改名前的中间产物去分发。
4. 依赖仓库：`maven.minecraftforge.net`（Forge userdev / MCP 数据）+ Maven Central
   （JavaCV/FFmpeg）。首次构建需要联网；之后走 Gradle 缓存。
5. 元数据：`META-INF/mods.toml` 用 `modLoader="javafml"`、`loaderVersion="[47,)"`、
   依赖 `forge [47,)` 与 `minecraft [1.20.1,1.20.2)`；`pack.mcmeta` 的 `pack_format = 15`；
   数据包目录是 **复数**：`data/vplayer/loot_tables/blocks/`、`data/vplayer/recipes/`。

## 4. 与 1.20.1 NeoForge 版的源码关系

`src/` 与 `minecraft-video-player-1.20.1-neoforge` 工程**逐文件一致**，只有两处不同：

- `src/main/resources/META-INF/mods.toml`：依赖范围改成 Forge（`forge [47,)`、
  `minecraft [1.20.1,1.20.2)`）。
- `src/main/java/com/vplayer/client/VPlayerClient.java`：自检（SelfTest，仅在游戏目录存在
  `vplayer-selftest.txt` 时启用，正常游玩无影响）在最后增加一步“打开屏幕控制界面并截图”
  `selftest-shot-gui.png`，用于自动核对控制界面能渲染、地址能回显。

即：1.20.1 的 API 差异（`new ResourceLocation`、`DeferredRegister`/`RegistryObject`、
`SimpleChannel`、`Block#use`、`TickEvent.ClientTickEvent + Phase.END` 等）在 1.20.1 NeoForge
工程里已全部处理过，Forge 版直接沿用。

## 5. 自检（游戏内自动测试）

游戏目录放 `vplayer-selftest.txt`（内容为一个视频文件的绝对路径，或 http(s) URL），
启动后模组会自动：摆 11×6 大屏 → 按南/北/东/西/朝下 + 不规则屏 + L 形屏依次播放并截图
→ 测暂停续播、挖掘掉落、3D 物品图标、控制界面 → 写 `vplayer-selftest-result.txt` 并自动退出。

通过标准：结果文件内容为
`OK 全部朝向 + 不规则屏幕 + L 形屏幕 + 暂停续播 + 挖掘掉落 + 图标`。

隔离测试实例（开发者自测用）：独立 gameDir，只读复用游戏目录的
`libraries`/`assets`/`versions\1.20.1-Forge_47.4.29`，不影响你自己的游戏实例。
运行前需要：`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`
（启动脚本是 UTF-8 BOM）。

## 6. 已知说明

- **FFmpeg 原生库**：模组自己把 jar 里的 dll 解压到 `<gameDir>\vplayer-natives\`，
  并在任何 JavaCPP 类初始化之前设置 `org.bytedeco.javacpp.pathsfirst` / `cachedir` /
  `platform.preloadpath`，再 `Loader.load`。这是 1.20.1 上能稳定加载 FFmpeg 的关键
  （历史问题：JavaCPP 从游戏类加载器反复解压已加载的 dll，Windows 报“另一个程序正在使用此文件”）。
- **停止/切换视频时**解码线程会打一条 `InterruptedException: sleep interrupted` 的 ERROR 日志，
  这是 1.21.1 / 1.20.1 NeoForge 同款既有行为（stop 时主动 interrupt 线程），不影响功能。
- 已知问题：“准星靠近屏幕时画面亮度会变暗”，暂不处理（与 1.20.1 NeoForge
  版同款渲染代码，现象可能相同，未定位、未修复）。
- 音频输出用 `javax.sound.sampled`，与 1.21.1 版实现相同。
