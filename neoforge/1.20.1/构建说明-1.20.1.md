# VPlayer 1.20.1（NeoForge）构建说明

本工程是 VPlayer 的 **Minecraft 1.20.1 + NeoForge（47.1.x，即 NeoForge 的 1.20.1 版本）** 移植工程，
功能与 1.21.1 版一致。1.20.1 这条线上 NeoForge 的包名仍是 `net.minecraftforge.*`（1.20.2 起才改名为
`net.neoforged.*`），所以源码里的 import 与 1.21.1 版不同。

## 1. 环境要求

| 项目 | 版本 |
| --- | --- |
| JDK | **Java 17**（`JAVA_HOME` 指向 JDK 17） |
| Gradle | 8.14.6（工程自带 wrapper，`gradle-wrapper.properties` 已指向腾讯云镜像） |
| Minecraft | 1.20.1 |
| NeoForge | 1.20.1-47.1.106（maven 坐标是 `net.neoforged:forge`，不是 `neoforge`） |
| 构建插件 | `net.neoforged.moddev.legacyforge` 2.0.91（ModDevGradle 的旧版 Forge/NeoForge 支持） |

## 2. 构建

Windows：

```powershell
$env:JAVA_HOME="C:\Program Files\Java\jdk-17"
cd <工程目录>
.\gradlew.bat build fatJar --no-daemon
```

产物：`build\libs\vplayer-1.0.0-all.jar`（约 122 MB，内含 FFmpeg/JavaCV 原生库）。

`fatJar` 任务会先把模组类 reobf 成 1.20.1 运行时需要的 SRG 名称，再合并 JavaCV/FFmpeg。
只保留 Windows 的 ffmpeg/javacpp 原生库（64 个 dll），排除 opencv/tesseract/openblas 等。

## 3. 本机/网络相关的特殊处理（build.gradle 里已写好）

1. **maven.neoforged.net 的 DNS 污染**：本机无法直连 `maven.neoforged.net`（官方 maven）。
   `build.gradle` 会把所有指向它的仓库地址自动重写到官方 CDN 镜像
   `https://neoforged.forgecdn.net`（同时镜像 `/releases` 与 `/mojang-meta` 两个根）。
   换到网络正常的机器时这段逻辑不会造成影响。
2. **NFRT 工件清单注入**：NeoFormRuntime（MDG 用来生成 Minecraft 工件的工具）默认自己联网下载
   `mcp_config` 等文件。这里用 `legacyNfrtExtras` 配置把 1.20.1 旧版管线需要的
   `mcp_config`/mergetool/installertools/jst/DiffPatch 等先由 Gradle 从可访问的仓库解析好，
   再通过 NFRT 的 `--artifact-manifest` 交给它，避免它直连被污染的 maven。
3. **reobf 命令行过长**：Windows 下单条命令行上限约 32K，reobf 任务默认会把几十个依赖 jar 当
   “继承数据 classpath”，会触发 `CreateProcess error=206`。这里改为只用合并后的单个 MC jar。
4. **开发环境 runClient**：`gradle runClient` 时 JavaCV 需要进入游戏的 GAME 类加载层，
   且其 jar 自带 `module-info`（声明 requires javafx.graphics）会让模块解析失败。
   `sanitizeJavacvJars` 任务生成一份去掉 `module-info` 的 dev 专用副本放进 legacy classpath。
   正式 fatJar 不受影响。
5. 如果本机 `~/.gradle/gradle.properties` 里配了代理，请确认代理正在运行；代理没开时 Gradle 会
   连代理失败（本工程构建时使用的是独立的 `GRADLE_USER_HOME`，见下）。

## 4. 1.20.1 与 1.21.1 源码的主要差异

- `ResourceLocation.fromNamespaceAndPath(ns, path)` → `new ResourceLocation(ns, path)`
- `DeferredRegister.Items` / `DeferredItem` → `DeferredRegister<Item>` + `RegistryObject`
- 网络：1.21.1 的 Payload → 1.20.1 的 `SimpleChannel`（`ScreenControlMsg` / `ScreenStateMsg`）
- `Block#useWithoutItem` → `Block#use`
- BlockEntity：`saveAdditional(CompoundTag)` / `load(CompoundTag)` / `getUpdateTag()` /
  `handleUpdateTag(CompoundTag)`（无 `HolderLookup.Provider` 参数）
- 客户端 tick：`ClientTickEvent.Post` → `TickEvent.ClientTickEvent` + `Phase.END` 判断
- 数据包目录：`data/vplayer/loot_tables/blocks/`、`data/vplayer/recipes/`（**复数**）；
  配方结果用 `"item": "vplayer:screen"`（1.20.1 格式）
- `pack.mcmeta` 的 `pack_format` = 15
- 元数据文件：`META-INF/mods.toml`（`modLoader="javafml"`，依赖 `forge` 与 `minecraft`）

## 5. 自检（可选）

工程带一个游戏内自动自检（`VPlayerClient.SelfTest`）：只要游戏目录下存在 `vplayer-selftest.txt`
（内容为一个视频文件路径），模组会自动摆 11×6 大屏、按南/北/东/西/朝下 + 不规则屏 + L 形屏
依次播放并截图，还测试暂停续播、挖掘掉落、3D 物品图标，最后写
`vplayer-selftest-result.txt` 并自动退出。

开发环境自检：

```powershell
# 在 run-mctest 目录准备一个世界，并写入视频路径
#   run-mctest/saves/selftest/...   （1.20.1 世界）
#   run-mctest/vplayer-selftest.txt （内容：视频文件的绝对路径）
.\gradlew.bat runClient --no-daemon
```

正式环境自检：把 `vplayer-1.0.0-all.jar` 放进 1.20.1 NeoForge 实例的 `mods/`，并在游戏目录放
`vplayer-selftest.txt`，启动游戏即可。

## 6. 已知说明

- FFmpeg 原生库由模组自己从 mod jar 解压到 `<gameDir>/vplayer-natives/`，并在任何 JavaCPP 类
  初始化之前设置 `org.bytedeco.javacpp.pathsfirst` / `cachedir` / `platform.preloadpath`。
  这是 1.20.1 上能稳定加载 FFmpeg 的关键（历史问题：JavaCPP 从游戏类加载器反复解压已加载的
  dll，Windows 报“另一个程序正在使用此文件”）。
- 本工程面向 **NeoForge 1.20.1（47.1.x）**。Forge 1.20.1（47.4.x）未做测试。
- 音频输出使用 `javax.sound.sampled`，与 1.21.1 版实现相同。
