# VPlayer 1.21.11（NeoForge 21.11）构建说明

## 1. 运行环境

| 项目 | 值 |
| --- | --- |
| 操作系统 | Windows 10 / 11（本机已验证 Windows） |
| JDK | **Java 21**（本机 `C:\Program Files\Java\jdk-21`） |
| Gradle | 9.2.1（`gradle/wrapper` 自带，distributionUrl 指向腾讯镜像） |
| 构建插件 | ModDevGradle `net.neoforged.moddev` **2.0.148** |
| Minecraft | **1.21.11** |
| NeoForge | **21.11.48** |
| 依赖 | `org.bytedeco:javacv-platform:1.5.11`（FFmpeg 解码/播放） |

版本号在 `gradle.properties`：`minecraft_version` / `neo_version` 必须成对匹配。

## 2. 构建命令

```powershell
$env:JAVA_HOME="C:\Program Files\Java\jdk-21"
cd <本工程目录>
.\gradlew.bat --no-daemon --console=plain build fatJar
```

产物：

- `build/libs/vplayer-1.0.0.jar`：普通模组 jar（不含 FFmpeg 原生库，开发用）
- `build/libs/vplayer-1.0.0-all.jar`：**可分发成品**（约 116 MB，含 64 个 Windows FFmpeg/javacpp dll），放进 `mods` 即可

## 3. 本机构建环境的两个坑（已自动处理）

1. **maven.neoforged.net 被 DNS 污染**（直连超时）：`build.gradle` 开头把 Gradle 解析到的
   `https://maven.neoforged.net/...` 仓库地址自动重写成官方 CDN
   `https://neoforged.forgecdn.net/...`（该镜像完整镜像 `/releases` 与 `/mojang-meta`）。
2. **全局 `%USERPROFILE%\.gradle\gradle.properties` 里可能配置了代理**（例如 `127.0.0.1:7897`），
   代理未启动时 Gradle 下载会 `Connection refused`。两个处理方式任选：
   - 启动代理（保持现有全局配置即可）；
   - 或给本次构建单独指定一个不带代理配置的 Gradle 用户目录，例如：
     ```powershell
     $env:GRADLE_USER_HOME="C:\gradle-home-vplayer"
     ```
     该目录下的 `caches`/`wrapper` 可用目录联接（junction）复用原 `%USERPROFILE%\.gradle` 的缓存。

首次构建会自动下载 Minecraft 1.21.11 / NeoForge 21.11.48 并反编译（约 2 分钟），之后增量编译约 10~30 秒。

## 4. 测试（隔离实例自检）

模组内置自动自检：在游戏目录放 `vplayer-selftest.txt`（写视频的本地路径或 http URL），启动客户端并进入一个已存在的单人世界
（`--quickPlaySingleplayer <世界名>`），模组会自动：高空摆 11×6 大屏 → 截未播放图 → 播放 → 截各朝向图 →
不规则屏幕 / L 形屏幕 / 暂停续播 / 挖掘掉落 / 3D 图标 / 控制界面 各自截图与判定 → 写
`vplayer-selftest-result.txt` → 自动退出。截图在游戏目录 `screenshots/` 下。

通过标准：结果文件内容为
`OK OK 全部朝向 + 不规则屏幕 + L 形屏幕 + 暂停续播 + 挖掘掉落 + 图标`，
并人工核对截图：画面单一完整、无重影/错位/接缝；L 形内拐角为实心边框；物品图标为 3D 方块。

> 测试实例必须独立（独立 gameDir + 独立 mods），不要用玩家的正式存档/实例。

## 5. 1.21.11 相对 1.21.1 的主要适配点（维护时注意）

- **渲染管线重写**：`BlockEntityRenderer` 改为「`createRenderState` / `extractRenderState` / `submit`」两阶段，
  自定义几何通过 `SubmitNodeCollector.submitCustomGeometry(PoseStack, RenderType, (pose, vertexConsumer) -> ...)` 提交；
  `RenderType`/`RenderTypes` 移到 `net.minecraft.client.renderer.rendertype` 包。
- **方块/物品 Properties 必须带 id**：用 `DeferredRegister.Blocks.registerBlock(...)`、
  `DeferredRegister.Items.registerSimpleBlockItem(...)`（不要直接用 `register(name, supplier)` + `Properties.of()`）。
- **方块实体存档**：`saveAdditional/loadAdditional` 改用 `ValueOutput`/`ValueInput`；
  网络同步 `getUpdateTag` 用 `saveWithoutMetadata(provider)`，客户端 `handleUpdateTag(ValueInput)`。
- **物品模型**：1.21.4+ 需要 `assets/vplayer/items/screen.json` 定义文件指向 `vplayer:item/screen` 模型。
- **配方**：1.21.11 的 `key` 里材料直接写字符串（`"minecraft:smooth_stone"`），旧的 `{"item": ...}` 形式会解析失败。
- **其它改名**：`ResourceLocation` → `Identifier`；`CommandSourceStack.hasPermission(int)` →
  `Commands.hasPermission(Commands.LEVEL_GAMEMASTERS)`；GUI 鼠标事件改为 `MouseButtonEvent`；
  `Direction.getNormal()` → `getUnitVec3i()`；`Level.isClientSide` 字段 → `isClientSide()` 方法；
  `Screenshot` API 改为异步回调。
- **无需 `pack.mcmeta`**：模组资源包由 NeoForge 以「可选元数据」方式加载，缺省即视为全版本兼容。
- FFmpeg 原生库加载方式与 1.21.1 相同（自解压到 `<gameDir>/vplayer-natives` 后让 JavaCPP 直接加载）。
